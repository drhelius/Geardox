# SeaBIOS for Geardox

SeaBIOS and SeaVGABIOS (https://www.seabios.org), the built-in system and VGA BIOS, taken from the `master` branch of
https://git.seabios.org/seabios.git at commit `28aa46349b97ef0ebf742ae4fb9f9fad03578670` (`rel-1.17.0-24`).
LGPLv3, see `COPYING.LESSER`.

Geardox compiles in the three ROM images, not the SeaBIOS sources. `seabios.cpp` holds them as byte arrays with the
version string, and is generated by `build.sh`, not edited by hand:

- `bios.config` builds the system BIOS for an ISA-only PC: QEMU paths without PCI devices, no USB, AHCI, virtio,
  NVMe, TPM, PCI BIOS, ACPI, SMBIOS or MP tables, APM on, A20 off when it jumps to the boot sector, 128 KB, messages
  on the debug port 402h.
- `vgabios.config` builds SeaVGABIOS for a plain IBM VGA, without PCI ROM headers.
- `vgabios_cirrus.config` builds SeaVGABIOS for the Cirrus Logic CL-GD5428 card, with its VBE, without PCI.

## Changes

`geardox.patch` holds every change against that commit:

- `__swab32` uses the C byte swap instead of `bswapl`. `bswap` is a 486 instruction and the fw_cfg code calls it, so
  on a 386 the first fw_cfg directory read raised an invalid opcode and the CPU shut down.
- `enable_vga_console` prints the Geardox title, the one in `Makefile.common` in code page 437 block characters,
  instead of the SeaBIOS version line, which still goes to the debug port.
- `make_bios_writable` and `make_bios_readonly` drive Geardox's shadow register at port 404h when it reads back
  `GDOX`, as they drive the i440FX PAM registers on QEMU. Locked at the end of POST, the option ROMs and the F segment
  are read-only and the space between `rom_get_last()` and `rom_get_max()` has nothing there, so UMB managers find
  it free.
- `apm_shutdown`, behind APM's power off, also writes 1 to port 408h, next to the shadow register, which powers
  Geardox's board off.
- `handle_1588` and `handle_15e801` give extended memory up to the end of the RAM that starts below 1 MB, not up to
  the top of RAM: with a Cirrus card and 16 MB or more Geardox's board leaves a hole at 15-16 MB for the card's linear
  frame buffer and hands SeaBIOS its map through fw_cfg `etc/e820`.
- INT 13h on floppies, after the IBM PS/2 and PC BIOS Interface Technical Reference (S68X-2341-00):
  - AH=15h gives a floppy drive's DASD type, 2 with a change line and 1 without. SeaBIOS gave 1 for every floppy.
  - AH=16h reads the drive's change line with its motor on, and forgets the media when the line is set. SeaBIOS
    always answered that the disk had changed.
  - AH=17h and AH=18h set the DASD type and the media type for a format (p2-55, p2-56), and AH=18h returns the
    diskette parameter table in ES:DI. SeaBIOS didn't have them.
  - AH=00h keeps the media it knew: the drive is recalibrated, and the media is sensed again only when it is unknown or
    the change line is set.
  - The data rate goes to the controller on every access, since the last one may have been to the other drive.
  - A format with the media unknown, as on an unformatted disk that can't be sensed, takes the drive's own type.
  - Seeks double the cylinder on double stepping media, a 360 KB disk in a 1.2 MB drive. SeaBIOS set the flag but
    stepped to the disk's own cylinder.
- POST sets equipment bit 12 when port 201h's axis bits read 0, as a game port's do before a trigger, and INT 15h
  AH=84h reads the buttons (DX=0) and the four axes (DX=1) as the IBM 5170 BIOS does (11/15/85 listing, p5-165 and
  p5-166). IBM enables interrupts while it reads, but a SeaBIOS handler can't take one on its stack, so the timer
  tick waits for the return.
- `vga_set_mode` turns the screen off (SR01 bit 5) for the whole mode set and on again at the end. The VGA mode set
  writes the mode's SR01 with bit 5 set, as the Cirrus tables already do. SeaVGABIOS loaded the DAC with the screen
  on and cleared memory after turning it on, so a frame could show the old picture in the new palette. IBM asks for
  the blank while the DAC is written (VGA and XGA Technical Reference, May 1992, p2-106).
- The VGA mode set writes the misc register before the CRTC, which answers only at the block the misc register
  selects. SeaVGABIOS wrote it after, so going between mono and colour modes sent the CRTC registers to the block
  that wasn't answering.
- The attribute controller's flip-flop is reset through input status 1 at 3BAh when the misc register selects mono:
  a VGA in mono mode doesn't answer at 3DAh.
- The Cirrus code was written for QEMU's PCI CL-GD5446. For an ISA or VL-Bus CL-GD5428:
  - The mode tables write SR07 without its upper nibble. On a CL-GD542x those bits map video memory at that MB, which
    put it at 1 MB.
  - The mode list and mode set take only the modes the installed memory holds. The 640x480x24 tables take a real
    CL-GD5428 BIOS's timing (clock/3 at 75.5 MHz) with the 1920-byte pitch VBE reports, and the other 24-bit modes stay off: QEMU's tables
    run a CL-GD542x at a third of their rate.
  - Going back to a VGA mode restores VCLK0 and VCLK1, which every Cirrus mode table rewrites.
  - VESA 100h, 640x400x8, is added as Cirrus mode 5Eh with the VGA's 400-line timing at 70 Hz.
  - The VBE window function that 4F01h's WinFuncPtr points to is a port I/O stub on the Cirrus build. SeaVGABIOS's
    goes through the INT 10h entry, which zeroes the high bits of ESP and loads the BIOS data segment, so a game
    calling it from protected mode crashed (Warcraft II).
  - 4F0Ah, VBE 2.0's protected mode interface, returns a table on the Cirrus build: set window, set display start and
    set palette as 32-bit code over ports only. SeaVGABIOS reports VBE 3.0 but failed the call, and games that take
    a 2.0 or later VBE to have it jumped through garbage (Warcraft II).
  - `clext_set_displaystart` writes start address bits 16-19 to CR1B and CR1D. It wrote bits 8-11, so a start past
    256 KB landed elsewhere.
  - Without PCI, the linear frame buffer is the chip's own aperture at 15 MB, when extended memory in CMOS 30h-31h
    ends at or below it, enabled in every extended mode.

## Building

`build.sh` clones the commit into a temporary folder, writes its version to `.version` and removes `.git`, applies
`geardox.patch`, builds the three images with `EXTRAVERSION=-geardox` and regenerates `seabios.cpp`. The version string
stays `rel-1.17.0-24-g28aa4634-geardox`, so the same toolchain gives the same bytes on every run.

It needs an i386 capable GCC and binutils: `i686-elf-gcc` on macOS (`CROSS_PREFIX=i686-elf-`, the default), the
system GCC on x86 Linux (`CROSS_PREFIX=`). `SEABIOS_REPO` can point to a local clone.

To update SeaBIOS, change `SEABIOS_COMMIT`, refresh `geardox.patch` against it if it no longer applies, and run
`build.sh`.
