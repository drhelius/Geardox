# FreeDOS for Geardox

The FreeDOS files of the disks Geardox makes: FreeDOS 1.4, April 2025, kernel 2043 and FreeCOM 0.86a, from the
packages in `packages`. Geardox compiles in the result, not the programs' sources.
`freedos.cpp` holds it as byte arrays and is generated by `build.sh`, not edited by hand:

- `k_freedos_files`: a ZIP with C:'s tree, fixed dates and order.
- `k_freedos_boot`: the FAT16 boot sector, assembled from `boot/boot.asm` in the kernel package.
- `k_freedos_mbr`: the MBR, assembled from `BOOTNORM.ASM` in the FDISK package. Every disk Geardox makes carries it.

Geardox's own DOS programs, GDXRUN, GDXDBG, POWEROFF, GDXIDLE and the boot code of a disk with no system, aren't FreeDOS's.
They live in `src/dos`, with their own `build.sh`.

## What's on the disk

`KERNEL.SYS` is the kernel's `KERNL386.SYS`, because every Geardox model is a 386 or better, without its sign-on: `build.sh` unpacks it, empties the sign-on's format string and packs it
again. `COMMAND.COM` is FreeCOM's with its internal `TITLE` command made unreachable (`build.sh` turns the name's first
letter in the command table into 01h), so a game's own `TITLE.EXE` runs, as in MS-DOS. Everything else is a program
from the packages, in `\FREEDOS\BIN`, and the license texts are in `\FREEDOS`.
`CONFIG.SYS` and `AUTOEXEC.BAT` aren't in the ZIP: Geardox writes them for each disk it makes, the built-in FreeDOS disk
and game disks alike. Geardox also adds GDXRUN, GDXDBG and POWEROFF to `\FREEDOS\BIN` from `src/dos`.

CTMOUSE and SHSUCDX wait for the mouse and CD-ROM hardware. NE2000 is Crynwr's packet driver, from the
`crynwr` package, which game disks load with GDXIPX when the machine has the network card. LBACACHE is the read cache a game descriptor's
`cache = on` loads. MKEYB is the small keyboard driver FreeDOS game disks load instead of KEYB when they have no upper
memory: KEYB leaves a gap of about 28K below its data there, and MKEYB stays under 1K. Disks on the user's own MS-DOS take CTMOUSE, UDVD2, `COPYING`, and SHSUCDX for MS-DOS 5.0, from
here into their `\GEARDOX`, next to GDXRUN, GDXDBG, POWEROFF and GDXIDLE from `src/dos`, and DOSKEY from `dependencies/doskey`.

## Building

`build.sh` checks `packages.sha256`, takes the files, assembles the two sectors and writes `freedos.cpp`. The same Python,
NASM and UPX give the same bytes on every run. It needs the three, and no network.

The kernel is UPX packed inside the kernel's own wrapper, a CONFIG block before it and a start-up trailer after it.
`build.sh` gives the packed part an EXE header, unpacks it with `upx -d`, packs it again with
`upx --8086 --best --no-reloc`, the kernel makefile's options without relocations, and rebuilds the wrapper with the
new sizes and stack. Newer UPX ends its decompressor with a jump relative to the load segment, so `build.sh` puts back
the far jump to the kernel's fixed segment that older UPX made.

To update FreeDOS, replace the zips and their hashes, and run `build.sh`. A disk already made isn't touched: it's the
user's, and only a new one gets the new files.

`repositories/1.4` on ibiblio is rolling, so these packages are kept here rather than downloaded.
